## 1. 왜 비정형 데이터에는 '딥러닝'이 필수일까?

오전 세션에서는 데이터의 형태와 딥러닝의 필요성을 짚고 넘어갔습니다. 엑셀이나 DB처럼 행과 열이 명확한 정형 데이터와 달리, **음성·이미지·영상·PDF 같은 비정형 데이터**는 사람이 일일이 특징(Feature)을 정의하기 어렵습니다. 특히 PDF 문서 안의 표처럼 글과 그림이 섞인 자료는 모델이 행과 열의 구조를 그대로 읽지 못하는 경우가 많죠.

* **전통적 머신러닝:** 사람이 특징을 추출해서 모델에 입력
* **딥러닝(CNN 등):** 픽셀 단위의 선·경계에서 시작해 질감과 복잡한 형태까지 **계층적으로 특징을 스스로 학습**

또한 강사님께서 **"프롬프트만으로 간단한 웹사이트는 만들 수 있어도, 상업적 개발과 유지보수에는 한계가 있다"**며 수학과 컴퓨터공학 기초를 다진 뒤 LLM, LangChain·LangGraph, 멀티에이전트로 확장할 것을 강조하신 점이 무척 와닿았습니다. AI가 코드를 짜주더라도 결국 함수와 변수의 역할을 알아야 결과를 검증하고 목적에 맞게 튜닝할 수 있으니까요.

## 2. VS Code + Python 3.13 기반 CNN 딥러닝 실습

오후에는 본격적으로 **Visual Studio Code**를 열고 이미지 분류 딥러닝 실습을 진행했습니다. 주피터 노트북(`.ipynb`) 환경은 장시간 학습 시 실행이 끊기는 이슈가 있어, 이번 실습은 안정적인 로컬 Python 스크립트 기반의 VS Code 환경(Python 3.13 + TensorFlow 호환 세팅)으로 진행되었습니다.

### ① 실습 데이터셋과 전처리: 클래스 불균형(1:4) 잡기
* **데이터셋:** AI 허브 **[주요 질환 이미지 합성 데이터]** 중 흉부 학습·검증 원천 데이터
* **데이터 구조:** 흑백 **1채널, 총 5개 클래스** (정상 이미지 5,000장 + 나머지 4개 질환 클래스 각 1,250장)

여기서 실무적으로 가장 중요했던 포인트는 **데이터 불균형(Class Imbalance) 보정**이었습니다. 정상 데이터가 질환 데이터보다 4배나 많기 때문에, 그냥 학습시키면 모델이 무조건 '정상'으로 찍어도 정확도가 높게 나오는 착시가 발생합니다.

이를 해결하기 위해 코드에서는 **클래스 가중치(Class Weight)**를 정상 클래스에 `1`, 소수 질환 클래스에 `4`로 부여하여 소수 클래스의 오답에 더 큰 페널티를 주도록 설계했습니다. *(여담으로, 한글 경로 인식 오류를 피하기 위해 폴더명을 모두 영문으로 통일하는 세심한 팁도 실전에서 아주 유용했습니다!)*

### ② 모델 파이프라인과 학습 제어 (`EarlyStopping` & `ModelCheckpoint`)
실습 코드는 이미지를 불러와 흑백 배열로 변환하는 유틸리티 모듈과, 모델 학습·평가를 담당하는 메인 스크립트로 깔끔하게 분리되어 있었습니다.

```text
[입력(1채널 흑백)] ➔ [합성곱(3×3 필터) + ReLU] ➔ [최대 풀링(Max Pooling)] ➔ [평탄화(Flatten)] ➔ [완전연결층 + Softmax]
```

* **CPU 학습 소요 시간:** 약 20~30분
* **과대적합 방지 전략:** 최대 250 에포크까지 설정할 수 있지만, 검증 손실(`val_loss`)이 3회 연속 개선되지 않으면 학습을 멈추는 **조기 종료(`EarlyStopping`, `patience=3`)**와 가장 성능이 좋았던 시점의 가중치를 저장하는 **모델 체크포인트(`ModelCheckpoint`)**를 적용했습니다. 실제로 30회 설정 시 20여 회 부근에서 조기 종료되며 최적점을 찾아냈습니다.

### ③ 결과 해석: 정확도 99.6%의 함정과 오답 노트
학습이 끝난 뒤 결과 폴더에는 4가지 핵심 산출물이 자동 생성되었습니다.

1. **학습 곡선 (Learning Curve):** 훈련 손실은 줄어드는데 검증 손실이 다시 튀어 오르는 과대적합 구간 점검
2. **혼동 행렬 (Confusion Matrix):** 어떤 질환 클래스끼리 자주 헷갈리는지 한눈에 파악
3. **성능 보고서:** 단순 정확도(Accuracy) 외에 **균형 정확도(Balanced Accuracy), 정밀도(Precision), 재현율(Recall), F1-score** 확인
4. **예측 CSV:** 개별 이미지별 실제 라벨과 예측값을 대조하여 오분류 케이스 직접 추적

시연에서 훈련 정확도가 **99.6%**까지 올라갔음에도 특정 클래스에서 예측 오류가 발생하는 사례를 함께 분석했는데, **"수능(테스트) 점수를 올리려면 모의고사(검증) 오답 노트를 보고 데이터 증강이나 드롭아웃, 학습률을 재조정해야 한다"**는 비유가 딥러닝 튜닝의 본질을 정확히 꿰뚫어 주었습니다.

## 3. AI 허브 데이터 안심존 체험: 고비용·민감 데이터의 보고

실습 마지막 시간에는 **원격 데스크톱(VDI)을 통해 데이터 안심존 분석 환경**에 직접 접속해 보았습니다. 안심존 내부는 크롬 기반의 주피터 환경과 우분투(Ubuntu) 기반 분석 환경으로 구성되어 있었고, 외부 반출이 엄격히 통제된 실제 미개방 데이터셋을 열람할 수 있었습니다.

### 안심존 이용 핵심 요약
* **온라인 vs 오프라인 안심존:** 온라인 안심존은 클라우드로 원격 접속해 **NVIDIA Tesla V100** 같은 고성능 GPU(대기 약 1개월 소요)나 CPU 환경(50GB 스토리지)을 활용할 수 있고, 오프라인 안심존은 전국 13개 지정 구역에 직접 방문해 민감 데이터를 분석합니다.
* **신청 및 심의:** 최대 10개 데이터셋까지 신청 가능하며, 이용 계획서와 보안 서약서(헬스케어 데이터는 IRB 심의 통지서 포함) 제출 후 약 2주간의 심의를 거칩니다.

강사님 말씀에 따르면 의료 영상 데이터는 구축·심의 비용이 어마어마해서 **영상 1장당 5만~10만 원, 데이터셋 하나에 수백만~수천만 원**의 가치가 있다고 합니다. 안심존 체험 환경에서 구강 2D·3D 이미지와 의료 표준 포맷인 **DCM(DICOM) 파일**을 파이썬 코드로 직접 경로 지정해 열어보면서, 개인 개발자가 접근하기 힘든 고품질 원천 데이터를 안전하게 학습할 수 있는 인프라가 생각보다 훨씬 체계적으로 갖춰져 있다는 인상을 받았습니다.

*(영상 분야에서도 한국 콘텐츠 VLM 데이터, K-콘텐츠 자막·서체·인물 페르소나 데이터 등 한국어 맥락이 살아있는 멀티모달 데이터셋이 다양하게 구축되어 있어, 추후 한국형 VLM이나 콘텐츠 생성 프로젝트에도 요긴하게 쓸 수 있겠다는 생각이 들었습니다.)*
